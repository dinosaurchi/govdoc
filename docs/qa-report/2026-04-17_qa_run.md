## Bugs found

### [BUG-001] consultation_notes missing from DocumentListOut schema
**File:** `api/app/schemas/document.py`
**Severity:** High (breaks /consultation page)
**Description:** DocumentListOut does not include `consultation_notes` field, causing TypeError "Cannot read properties of undefined (reading 'length')" on `/consultation` page when filtering `d.consultation_notes.length > 0`.
**Fix:** Add `consultation_notes: list` to DocumentListOut OR use GET /documents/{id} on consultation page.

---

### [BUG-002] State machine: routed → in_consultation transition invalid
**File:** `api/app/services/workflow.py`
**Severity:** Critical (breaks hero flow)
**Description:** After approve-routing sets status to `routed`, request-consultation fails with `Invalid transition: routed → in_consultation`. The workflow only allows `routed → under_review` or `routed → out_of_scope`. This means the hero flow (intake → reviewer approves → reviewer requests consultation) cannot complete via the UI because the missing `under_review` state blocks `in_consultation`.
**Fix:** Either add `routed → in_consultation` transition to workflow, or ensure implicit `routed → under_review` happens on GET and the UI shows correct state.

---

### [BUG-003] make qa script missing role header
**File:** `scripts/qa_local.sh`
**Severity:** Medium (QA script bug)
**Description:** check #6 (documents list) sends GET /api/v1/documents/ without X-GovDoc-Role header, causing 400 MISSING_ROLE_HEADER.
**Fix:** Add `-H "X-GovDoc-Role: reviewer"` to that curl command.

---

### [BUG-004] Consultant role in UI maps to unknown API role
**File:** `web/src/lib/api.ts:8`
**Severity:** Medium (UX bug)
**Description:** ROLE_MAP includes `'Consultant': 'consultant'` but roles.yaml has no consultant role. Selecting Consultant returns 403 UNKNOWN_ROLE on every API call.
**Fix:** Either remove Consultant from ROLE_MAP or add consultant role to roles.yaml.
