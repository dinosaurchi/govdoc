The repo still contains duplicate-looking root-level folders such as:
- `app/`
- `hooks/`
- `lib/`

outside the intended `web/` app structure.

Retrieval is still coupled into the extraction service area instead of being clearly separated into its own provider/module boundary.

That matters because later:
- retrieval
- extraction
- OCR

Even for baseline quality, the `documents` endpoint is still returning trivial hardcoded payloads instead of using the repository/service structure consistently.

Pass 2 is supposed to make frontend+backend behavior real; but the baseline should at least have a cleaner API/service skeleton first.

### 4. Makefile / README / local workflow are still too thin
The scaffold exists, but it is still too minimal and not yet a stable enough baseline handoff:
- Makefile still lacks clearer baseline workflow shape
- README is still too thin for what this repo now contains
- local dev / boot expectations are not yet expressed clearly enough

### 5. Frontend still contains a lot of fake-real hardcoded content
That is okay in early scaffolding, but before Pass 2 the frontend should more clearly point to typed backend/API placeholders instead of looking like complete behavior with fixed static data.

This does **not** mean “make it real now”.
It means “make the baseline honest and structurally clean before Pass 2”.
