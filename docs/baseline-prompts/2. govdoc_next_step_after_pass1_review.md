## Why Pass 1 is not “good enough” yet

### 1. Backend entity model is incomplete
The source-of-truth / implementation plan expects at least these baseline entities:
- document
- document_file
- extracted_artifact
- ai_analysis
- routing_decision
- consultation_note
- audit_event
- role
- department
- demo_scenario

Current repo only has partial coverage. Critical missing pieces include:
- `routing_decision`
- `consultation_note`
- `audit_event`
- `role`
- `department`
- `demo_scenario`
- `prompt_version`

### 2. The migration is a placeholder
Alembic migration exists, but the migration body is effectively empty. That means the DB scaffold is not really aligned yet.

### 3. Route/API scaffold is too thin
Current API only exposes a very small `/documents` placeholder. It does not scaffold the real shape needed for:
- consultation
- dashboard
- review actions
- demo scenarios
- routing/action endpoints
- role-aware flows

### 4. Role simulation exists only in frontend state
The role switcher is present in the frontend, but there is no real backend-side policy scaffold enforcing role-based access or action restrictions.

### 5. Service boundaries are not clean enough yet
There is some interface separation, but it is incomplete:
- retrieval is mixed into extraction interface file
- no clear workflow service facade is present
- repository/service layering is still too shallow for later coding-agent replacement work

### 6. The repo has structural noise / duplication
There are duplicate-looking root folders like:
- `app/`
- `hooks/`
- `lib/`

outside the `web/` app structure. That is risky and should be cleaned now before deeper implementation starts.

### 7. Makefile / docker / README are not aligned enough
The current Makefile is too minimal for the intended baseline shape.
README and local run flow are also still too thin to be treated as the stable baseline handoff.

### 8. Some package/dependency choices look wrong or noisy
Examples:
- backend `requirements.txt` includes `sqlite3`, which should not be a pip requirement
- web package includes some tooling/deps that do not look necessary for this baseline
- root/package structure should be cleaned before pass 2

### 9. Frontend pages are visually useful, but still too hardcoded
That is acceptable for very early scaffolding, but before pass 2 the app should stop pretending to have real detail logic where it is only hardcoded content.
