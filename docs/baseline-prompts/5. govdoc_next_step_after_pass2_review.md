## Why it is not ready for Pass 3 yet

### 1. Intake is still a simulated create flow, not a real upload baseline
The intake page is still a “simulate upload” action rather than a real baseline file-upload path.

For the working baseline threshold, Pass 2 should already support:
- selecting/uploading a file
- creating a `document`
- creating a `document_file`
- creating at least one baseline `extracted_artifact` (mock extraction is fine)

Right now, the app is still closer to “create a document record” than “upload/intake baseline.”

### 2. `document_file` and `extracted_artifact` are still not meaningfully used
The source-of-truth and implementation plan expect the baseline to preserve the path toward:
- raw file reference
- normalized artifact
- later extraction/OCR replacement

That baseline data path is still too thin.

### 3. Pass 2 product behavior is still incomplete in places
Examples:
- detail page is better, but still not grounded in a fuller baseline document payload
- extracted metadata / raw file / artifact information are still not really surfaced
- some flows still look more simulated than “real baseline behavior with mocked internals”

### 4. Stray root frontend folders still remain
The repo still appears to contain root-level `app/`, `hooks/`, and `lib/` outside the intended `web/` structure.
That should already have been cleaned during Pass 2.

### 5. Pass 3 is the wrong place to fix these
Pass 3 should focus on:
- Makefile
- docker-compose hardening
- local QA
- credential checks
- remote deploy scaffold
- test scaffolding

If you move to Pass 3 now, Gemini may spend time on devops while the actual baseline product is still incomplete.
